# Frost 0.4.0 — plan

Spec: user request 2026-11-21: "it will have previews for pictures when clicking on them once (not opening them) and their info on the right side".

Goal: click a picture once (select it, don't open it) and a preview of it appears on the right, with its info underneath. Double-click still opens it in the default app. Ships for Windows and Linux.

## Where we start

- Both apps already have a preview pane (Alt+P), **off by default**. With it on, a selected image shows a small picture (Windows: shell thumbnail; Linux: decoded to 480 px) and basic info: type, size, modified, created.
- What's missing: the pane doesn't appear by itself when you click a picture, the picture is small, and there's no picture-specific info (dimensions, camera, date taken…).

## What 0.4.0 does

1. **Click a picture once → preview pane opens on the right** (if it isn't open already), showing the picture as large as the pane allows, sharp on high-DPI screens, correctly rotated (EXIF orientation).
2. **Info under the picture:**
   - Always: name, format (JPEG, PNG, WebP, GIF, BMP, HEIC…), dimensions (e.g. `4032 × 3024`, `12.2 MP`), file size, modified, created.
   - When the photo has EXIF: date taken, camera (make + model), lens, exposure (`1/120 s · f/1.8 · ISO 100`), focal length, location (lat/lon, with a "Copy" button).
   - Animated GIF/WebP: frame count. Images with transparency: "has transparency".
3. **Pane behaviour:**
   - Selecting something that isn't a picture closes the pane again, unless the user turned the pane on with Alt+P (then it stays, as today).
   - Pane width is resizable by dragging its left edge; the width is remembered.
   - Several pictures selected: show the first one plus "N pictures, total size".
   - Arrow keys move the selection as usual, so the preview follows; quick scrolling must not lag (cancel stale loads).
4. **Setting:** "⋯ → Preview pictures on click" (on by default) to turn the auto-open off.

Out of scope for 0.4.0: video previews, general EXIF editing.

## Standout features (what most file managers don't have)

Added 2026-11-21 ("add whatever else you think will make it stand out"). Ordered by value; 5–8 are the headline, 9–10 ship if time allows.

5. **Quick Look (Space).** Press Space on any file for a big floating Liquid Glass preview over the window, like macOS: pictures (zoom with wheel, drag to pan, fit/100% toggle), text and code (monospace, first 1 MB), ZIP contents, folders (item count + size), everything else (icon + info). ←/→ flips through the folder, Space or Esc closes, Enter opens. Explorer and Nautilus have nothing like it built in.
6. **Photo tools (right-click a picture, several at once).**
   - Rotate left/right (JPEG: rewrite EXIF orientation only, so no quality loss).
   - Convert to PNG / JPG / WebP and Resize (presets 50%, 1920 px, 1280 px, or custom), written as new files next to the originals ("photo (1920px).jpg"), never overwriting.
   - **Remove location** (strip GPS from EXIF): one click privacy before sharing photos. The info pane shows a small "📍 has location" badge so you notice.
   - Every change is undoable (Ctrl+Z), using the 0.3.0 undo history; in-place changes keep the original in the trash/Recycle Bin.
7. **Colour palette.** The info pane shows the picture's 5 main colours as swatches; click one to copy its hex code. Great for designers, nobody else does it.
8. **Space analyzer ("What's using space?").** "⋯" menu or palette: scans the current folder in the background and shows every subfolder/file as a bar sorted by size (with %), click to drill in, back to go up, cancel any time. Answers "why is my disk full" without another app.
8b. **Biggest files on every drive.** (Added 2026-11-21 at the user's request.) "⋯ → Find biggest files" or the palette: scans every drive at once (Windows: all fixed drives C:, D:, …; Linux: `/` and every mounted disk under `/mnt`, `/media`, `/run/media`, the same list as the sidebar's Drives) and shows, per drive, its free/used space and the **top 50 biggest files** (name, size, folder, modified), plus one combined "biggest overall" list. Drives are scanned in parallel in the background with live results as they're found, per-drive progress and cancel. Click a file to reveal it in a tab; right-click offers Open, Show in folder, Move to trash (undoable). Skips system/virtual filesystems (`/proc`, `/sys`, `/dev`, network mounts by default), never follows symlinks/junctions, and lists folders it couldn't read instead of failing.
9. **Split view.** Ctrl+\ shows two folders side by side (each with its own tabs); F6 switches side; drag, copy/paste and "Copy to other side" (F5 in split mode) between them. Power-user favourite from Total Commander, missing from Explorer.
10. **Duplicate finder.** Pick a folder → finds identical files (size first, then a fast hash, then a full hash to be sure), grouped, with "keep newest/oldest" helpers; selected duplicates go to the trash (undoable), never deleted permanently.

Also for Linux parity: **picture thumbnails in the Large / Extra large views** (Windows already has them via the shell), generated off-thread and cached in `~/.cache/thumbnails` using the freedesktop standard so they're shared with other file managers.

## Global constraints

- **Every feature ships in both versions, Windows (`Frost.App`) and Linux (`Frost.Linux`), with the same behaviour and shortcuts.** (Standing rule from the user, 2026-11-21.) A feature is done only when both have it; platform differences are limited to what the OS forces (e.g. drive list, codecs).

- Solution `Frost.slnx`; .NET 10. `dotnet build Frost.slnx` 0 errors, no new warnings. Core tests (152 today) and Linux tests (16 today) must pass; new features add tests.
- **No new NuGet packages.** Image headers and EXIF are parsed by our own small reader in `Frost.Core` (BCL only). Decoding uses what each UI already has: WPF/WIC on Windows, Avalonia/Skia on Linux.
- Logic in `src/Frost.Core` (pure, unit tested). UI in `src/Frost.App` (Windows) and `src/Frost.Linux`.
- Loading never blocks the UI: read/decode on a background thread, cancelled when the selection changes (both apps already debounce preview updates). Decode only to the pane's pixel size, not full resolution. Skip decoding above a safety cap (e.g. 200 MB or 100 megapixels) and show info only.
- Corrupt or unsupported files never crash: show the file icon + whatever info could be read.
- Match the existing Liquid Glass look and keyboard access; icon-only controls get accessible names.

### Task 1: Core — `ImageInfo` reader

New `src/Frost.Core/ImageInfo.cs`: `ImageInfo.TryRead(path)` reads only the header bytes (never the whole file) and returns format, width, height, orientation, frame count, hasAlpha, plus EXIF fields when present.
- Formats: JPEG (SOF markers + APP1 EXIF), PNG (IHDR, acTL for APNG), GIF (logical screen + frame count), BMP, WebP (VP8/VP8L/VP8X, ANIM), HEIC/AVIF (`ispe` box for dimensions; EXIF if easy, else none), TIFF.
- EXIF: TIFF IFD0 + Exif sub-IFD + GPS IFD, both byte orders; DateTimeOriginal, Make, Model, LensModel, ExposureTime, FNumber, ISO, FocalLength, GPS lat/lon → decimal degrees, Orientation.
- Hardening: bounds-check every offset/length, cap IFD entry counts, no loops on cyclic offsets; malformed data returns partial info, never throws.
- `Format` helpers: `12.2 MP`, `1/120 s`, `f/1.8`.
- Tests `tests/Frost.Core.Tests/ImageInfoTests.cs`: tiny generated files per format (built in the test from bytes), crafted EXIF (both byte orders, GPS south/west), truncated/garbage files, cyclic IFD.

### Task 2: Windows UI (`src/Frost.App`)

- `PreviewViewModel`: when the selection is one picture, load a large preview off-thread with WIC (`BitmapImage`/`BitmapDecoder`, `DecodePixelWidth` = pane width × DPI, EXIF rotation applied), fall back to the shell thumbnail for formats WIC can't decode (HEIC without the codec), and fill the new info fields from `ImageInfo`.
- Auto-open/close logic and the "Preview pictures on click" setting (`Settings.cs`); a resizable pane width (GridSplitter) saved in settings.
- Info section in `MainWindow.xaml` under the picture: label/value rows, "Copy" next to location.
- README tester-checklist items for Windows (untestable here; a friend tests on Windows 11).

### Task 3: Linux UI (`src/Frost.Linux`)

- Same behaviour in `UpdatePreview`: decode with `Bitmap.DecodeToWidth` to pane width × render scaling, apply EXIF rotation, info rows from `ImageInfo`. Formats Skia can't decode (HEIC/AVIF/SVG) show the icon + info.
- Auto-open/close, setting, resizable pane (GridSplitter), saved width.
- Headless tests in `tests/Frost.Linux.Tests`: click a PNG → pane visible, image shown, info contains `W × H`; click a .txt → pane closes again; Alt+P keeps it open; setting off → no auto-open; corrupt .jpg → no crash, icon shown.
- Real-input check on the private Xwayland display (like 0.3.0): single-click pictures, arrow through a folder of large photos, check it stays responsive.

### Task 5: Core for the standout features

Pure, tested logic in `Frost.Core`, so both UIs share it:
- `ExifEdit`: set orientation and remove GPS in JPEG EXIF **in place of the APP1 segment only** (image data untouched), writing to a temp file then swapping; refuse files it can't parse rather than risk damage. Tests: round-trip, GPS gone, image bytes identical, malformed input refused.
- `Palette.Extract(pixels)`: 5 dominant colours (k-means or median cut on a downscaled copy); the UI passes decoded pixels. Tests on synthetic images.
- `SpaceScan`: async folder size tree with progress/cancel, skips symlinks/reparse points (no loops), counts unreadable folders as "can't read". Tests on temp trees.
- `BiggestFiles.ScanAsync(roots, topN, progress, ct)`: walks each root on its own task, keeps a top-N min-heap per root plus an overall top-N (memory stays small on multi-TB disks), reports partial results while scanning, stays on the root's filesystem (no crossing into other mounts), skips symlinks/reparse points and excluded paths. Tests: top-N correctness, ties, unreadable folders, symlink loops, cancellation.
- `Duplicates`: size → 64 KB partial hash → full SHA-256 grouping, progress/cancel. Tests incl. same size different content.
- Image convert/resize stay in the UIs (WIC encoders on Windows, Skia on Linux) behind one small interface.

2. **Unmerged transparency work:** branch `feat/transparency` (Windows window transparency slider + Mica/Acrylic, done 2026-11-20, untested on Windows) could ship in 0.4.0 too, or stay out.

## Risks

- Windows UI can't be run here; only build + Core tests are verified on Linux. The Windows preview needs a real Windows test before release.
- HEIC/AVIF preview depends on codecs (Windows: HEIF extension from the Store; Linux: not supported by Skia). Those still get dimensions and info.
- Very large images: mitigated by downscaled decode, the size cap and cancellation.
- Photo tools change user files: in-place edits only touch EXIF, go through temp-file-then-swap, keep the original in the trash, and are undoable; anything unparseable is refused.
- Scope: Tasks 5–7 roughly triple 0.4.0. Order of work is 1 → 2/3 → 5 → 6 → 7 → 4; if it runs long, split view and duplicates (items 9–10) move to 0.5.0 rather than delaying the release.
