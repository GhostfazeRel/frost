Spec: user request 2026-11-20: "make the frost file manager much better and add a new release to github; use ~4 parallel subagents". No further spec; feature choice below is the controller's ruling.

Four features are built in parallel, each by one agent in its own git worktree on its own branch off `release/0.3.0`, then merged; an integration task follows.

- Merge-friendliness (four agents edit in parallel): put new code in NEW files — Core class files, new windows, and a partial-class file `src/Frost.App/MainWindow.<Feature>.cs` (MainWindow is `partial`). Edits to existing shared files (`MainWindow.xaml.cs`, `MainWindow.xaml`, `MainViewModel.cs`, `TabViewModel.cs`) must be minimal hook lines only (a key case in `Window_PreviewKeyDown`, a menu entry where the "…" menu or the item context menu is built, a one-line call). Do NOT reformat or reorder existing code. Do not edit README.md or the version — the integration task does; put your README text (feature paragraph, shortcut, tester-checklist item) in your report.
- UI must match the existing Liquid Glass look: reuse styles/brushes from `Themes/Glass.xaml` and the existing `DialogWindow` pattern; keyboard accessible; AutomationProperties.Name on icon-only controls.
- Long file work runs off the UI thread with progress + cancel through the existing operations UI (`OperationViewModel`, `OperationProgress`), like copy/move do today.
- Safety: never overwrite or delete user data unexpectedly; on conflict refuse with a clear message rather than guess.
- Commit on your branch with clear messages (`Frost 0.3.0: <feature>: …`), ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push, never touch `main`, never create releases.

### Task 1: Undo / Redo for file operations

Branch `feat/undo`. Ctrl+Z undo, Ctrl+Y and Ctrl+Shift+Z redo, plus "Undo <action>" / "Redo <action>" entries in the "…" menu (disabled when empty), with a short toast or status notice saying what was undone.
- Core `UndoHistory`: records reversible operations as data — Rename(from, to), Create(path) (new folder/file), Transfer(move: bool, pairs of source→actual destination), Recycle(original paths). Computes the inverse; App executes it. Cap 50 entries; a new operation clears redo.
- `TransferAsync` must report the actual destination paths (after collision renaming like "file (2).txt") so undo is exact — this task owns any change to `FileOperations.cs`.
- Inverses: rename back; created item → Recycle Bin (only if it still exists); copy → recycle the copies; move → move back; recycle → restore from the Recycle Bin via the Shell (e.g. Shell namespace of the Recycle Bin, matching original path + deletion time, invoking the restore/"undelete" verb). If restore cannot be done reliably, show "Can't undo delete — open Recycle Bin" with a button that opens it. Permanent delete is not undoable.
- Before undoing, verify every path involved is still in the expected state (target exists, original location free); if not, refuse with a message, never overwrite.
- Expose one method the App uses to record an operation (`RecordRename(from,to)` etc.) so other features (batch rename) can record too.
- Tests: inverse computation, cap, redo clearing, state-check refusal (use temp dirs).

### Task 2: ZIP archives

Branch `feat/zip`.
- Core `Archives`: `CompressAsync(paths, destZipPath, progress, ct)` and `ExtractAsync(zipPath, destDir, progress, ct)` with System.IO.Compression. Zip-slip protection (any entry resolving outside destDir → error, nothing written outside). Unique output names ("Photos.zip" → "Photos (2).zip"; extract folder "Photos" → "Photos (2)"). Cancel or failure removes the partial output. Progress in bytes through `OperationProgress`.
- Right-click (Frost's own item context menu): "Compress to ZIP" for any selection (name = single item's name, or the folder's name for multi-select); for `.zip` files "Extract here" (into a new folder named after the zip, in the current folder) and "Extract to…" (folder picker). Runs in the operations panel with cancel. The new zip/folder is selected after completion if simple.
- Preview pane: for a `.zip`, show entry count, total uncompressed size and the first 200 entry names (this task owns `PreviewViewModel.cs` changes).
- Tests: round-trip compress→extract incl. nested folders and empty folders, unicode names, zip-slip rejection, unique naming, cancellation cleanup.

### Task 3: Batch rename

Branch `feat/batch-rename`. F2 with 2+ items selected (or right-click "Rename…" on a multi-selection) opens a Batch Rename window; F2 on a single item keeps today's inline rename.
- Core `BatchRename`: `Plan(IReadOnlyList<string> paths, BatchRenameOptions o)` → list of (oldPath, newName, error?). Options: find/replace (plain or regex, match case), prefix, suffix, numbering (`{n}` token with start, step, zero-padded width), case (unchanged/lower/UPPER/Title), apply to name only or name+extension. Errors: invalid characters/reserved names (CON, NUL…), empty name, duplicate targets within the batch, target already exists (case-insensitive like Windows, but a pure case change of the same file is allowed). `Apply(plan)` renames in two phases via temporary names so swaps (a→b, b→a) and case-only renames work; on failure, roll back what was done.
- Window: options on top, live preview list (old → new, errors highlighted red with tooltip), Rename button disabled while any error. Glass style, Esc cancels, Enter applies.
- Return the applied (old, new) list from Apply so integration can record undo entries.
- Tests: each option, numbering, regex groups, swap, case-only rename, all error kinds, rollback.

### Task 4: Command palette + Go to folder

Branch `feat/palette`. Ctrl+Shift+P opens a command palette; Ctrl+P opens "Go to folder".
- Core `Fuzzy`: `Score(query, candidate)` → score + matched character indices (subsequence match, bonuses for word starts / after separators / consecutive runs / prefix, case-insensitive); returns null for no match. Ranking helper. Tests for ordering and indices.
- Palette overlay window (glass, top-center of the main window, closes on Esc / focus loss): text box + result list with matched characters highlighted, Up/Down/Enter, mouse click. Commands: every existing action reachable from keys or menus (new tab, close tab, reopen tab, views, sort options, toggle preview, refresh, new folder, address bar, search, pin folder, open terminal here if it exists, make default / restore Explorer, check for updates…) with their shortcut text; implement as a list of (title, gesture, action) built in `MainWindow.Palette.cs` calling existing handlers/VM methods.
- Go to folder: candidates = recently visited folders (new `RecentFolders` list in `Settings`, most-recent first, max 50, recorded on navigation, missing folders skipped), quick access/pinned, drives, and subfolders of the current folder. Typing an absolute path that exists offers "Go to <path>" first. Enter navigates current tab; Ctrl+Enter opens in a new tab. (This task owns `Settings.cs` changes.)
- Tests: Fuzzy scoring/ordering; recent-folders list behaviour (dedupe, cap, order) if it lives in Core.
